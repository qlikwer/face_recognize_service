# Face Recognition Encoder Service (Docker)

HTTP-сервис-**энкодер** лиц на базе `face_recognition`/dlib, упакованный в Docker. Задуман как удалённый движок распознавания для интеграции **intersvyaz** (Home Assistant), когда локальный dlib в HA несовместим с CPU (падает сигналом SIGILL на процессорах без AVX).

---

## 🧩 Архитектура

Сервис **не хранит** список известных людей и не сравнивает лица между собой — это делает вызывающая сторона (интеграция intersvyaz в Home Assistant). Сервис только:

1. принимает изображение,
2. находит на нём лица,
3. возвращает 128-мерные dlib ResNet дескрипторы (и координаты лиц для `/v1/encode/multi`).

```
Home Assistant (custom_components/intersvyaz)
        |
        | HTTPS/HTTP + Bearer token
        v
Docker container (Debian)
  ├─ FastAPI
  └─ face_recognition / dlib (собран без AVX — см. Dockerfile)
```

Хранение эталонов лиц, сопоставление по порогу, привязка к `person.*`, события и авто-открытие — всё остаётся на стороне Home Assistant, как и для встроенных (локальных) движков интеграции.

---

## 🔐 Авторизация

Обязательна переменная окружения `FACE_API_TOKEN`. Сервис **не запустится** без неё. Все эндпоинты требуют заголовок:

```
Authorization: Bearer <FACE_API_TOKEN>
```

Контейнер не предназначен для публикации в интернет — используйте только в своей локальной сети (или за VPN).

## 📡 API

### `GET /health`

Проверка живости + версии движка (используется интеграцией для валидации настроек и как признак восстановления после сбоя).

```json
{"status": "ok", "engine": "remote_dlib_resnet_v1", "encoding_size": 128, "detector_model": "hog"}
```

### `POST /v1/encode/single`

Энкодинг эталонного фото — требует **ровно одно** лицо.

* Вход: `multipart/form-data`, поле `image`; опционально `num_jitters` (по умолчанию 2).
* Успех (200): `{"encoding": [...128 float...], "faces_detected": 1}`
* Ошибка (422): `{"detail": {"error_code": "no_face" | "multiple_faces", "message": "...", "faces_detected"?: N}}`

### `POST /v1/encode/multi`

Детект + энкодинг всех лиц на кадре (для распознавания в реальном времени).

* Вход: `multipart/form-data`, поле `image`; опционально `num_jitters` (по умолчанию 1).
* Ответ (200): `{"faces_detected": N, "faces": [{"encoding": [...128...], "bbox": [top, right, bottom, left]}, ...]}`

Swagger UI: `http://<IP>:8000/docs`.

## 🐳 Docker Compose

```bash
FACE_API_TOKEN=$(openssl rand -hex 32) docker compose up -d --build
```

или создайте `.env` рядом с `docker-compose.yml`:

```
FACE_API_TOKEN=<сгенерированный_токен>
```

После запуска укажите тот же URL и токен в настройках интеграции **intersvyaz** → «Удалённое распознавание лиц».

## ⚠️ Примечания

* Первый запуск и сборка образа занимают несколько минут (сборка `dlib` из исходников).
* dlib собирается с явно отключёнными AVX/AVX2/SSE4-инструкциями (см. `Dockerfile`) — образ гарантированно запускается на старом CPU, но работает несколько медленнее, чем AVX-оптимизированная сборка. Если известно, что CPU хост-машины поддерживает AVX2, флаги можно убрать из `Dockerfile` для ускорения.
* Распознавание нагружает CPU — рекомендуется ограничить ресурсы контейнера.
* Контейнер не предназначен для публикации в интернет без дополнительной защиты (обратный прокси с TLS, allowlist по IP и т.п.) — токен защищает от случайного доступа, но не заменяет сетевую изоляцию.
